# IPTV / OTT mini-backend (Go)

Небольшой REST API для списка ТВ-каналов и получения ссылки на HLS live-поток. 

## Возможности

### Обязательная часть

- PostgreSQL: пользователи, каналы и подписки; схема и тестовые записи создаются при первом запуске приложения.
- HTTP Basic Auth. Неактивный пользователь, неизвестный логин или неверный пароль получают `401` и `WWW-Authenticate`.
- `GET /api/v1/channels` — каналы, доступные текущему пользователю.
- `GET /api/v1/channels/{id}/playback` — ссылка на HLS-плейлист.
- Единый JSON-формат ошибок; SQL-тексты и внутренние ошибки не возвращаются клиенту.
- Graceful shutdown по `SIGINT`/`SIGTERM`, ограниченные таймауты HTTP-сервера и ограничение размера JSON-тела.
- JSON-логи через `log/slog`; пароли и заголовки авторизации в лог не записываются.

### Реализованные усложнения

1. **Подписки.** Бессрочные и с датой окончания. Доступ выдаётся, только если пользователь активен, канал активен, подписка включена и срок не истёк.
2. **Административный API.** CRUD-подобное управление пользователями, каналами и подписками. Все маршруты `/admin/api/v1/...` требуют активную учётную запись с ролью `admin`.
3. **Кэширование.** Кэш успешной аутентификации и кэш списка доступных каналов по пользователю. Есть объединение одновременных одинаковых запросов аутентификации и загрузок списка каналов (singleflight-подобная реализация без дополнительной зависимости). Административные изменения инвалидируют затронутые кэши.

## Требования

- Go 1.26 или новее.
- Docker и Docker Compose.

## Запуск одной командой

В корне проекта:

```bash
docker compose up --build
```

При первом старте Compose поднимает PostgreSQL, ждёт успешного `pg_isready`, после чего API создаёт схему и тестовые данные. API слушает `http://localhost:8080`.

Для локального тестового запуска используются учётные записи:

| Роль | Логин | Пароль |
|---|---|---|
| Администратор | `admin` | `admin12345` |
| Абонент | `viewer` | `viewer12345` |

По умолчанию пароль PostgreSQL в `compose.yaml` — `local_iptv_password_change_me`. Для локального стенда это упрощает запуск без дополнительных файлов. Переопределить его можно через `POSTGRES_PASSWORD` в окружении. Не используйте значение по умолчанию за пределами локальной разработки.

Остановить сервис:

```bash
docker compose down
```

Данные PostgreSQL хранятся в named volume. Чтобы удалить и данные, и тестовую базу (необратимо):

```bash
docker compose down -v
```

Seed-данные добавляются через `ON CONFLICT DO NOTHING`.

## Конфигурация

| Переменная | По умолчанию | Назначение |
|---|---|---|
| `HTTP_ADDR` | `:8080` | Адрес HTTP-сервера |
| `DATABASE_URL` | обязательна | PostgreSQL DSN |
| `AUTH_CACHE_TTL` | `30s` | TTL успешной аутентификации; `0s` отключает кэш |
| `CHANNELS_CACHE_TTL` | `5s` | TTL списка каналов; `0s` отключает кэш |
| `MAX_BODY_BYTES` | `1048576` | Максимальный размер JSON-тела |

## API абонента

### Список доступных каналов

```bash
curl -i -u viewer:viewer12345 http://localhost:8080/api/v1/channels
```

Пример ответа:

```json
{
  "channels": [
    {"id": 1, "number": 1, "name": "Первый"},
    {"id": 2, "number": 2, "name": "Россия 1"}
  ]
}
```

### Получить ссылку на просмотр

```bash
curl -i -u viewer:viewer12345 http://localhost:8080/api/v1/channels/1/playback
```

Пример:

```json
{"channel_id":1,"url":"https://stream.example.com/live/ch1/index.m3u8"}
```

### Краевые случаи

```bash
# Неверный ID — 400
curl -i -u viewer:viewer12345 http://localhost:8080/api/v1/channels/not-a-number/playback

# Несуществующий, выключенный или недоступный по подписке канал — 404
curl -i -u viewer:viewer12345 http://localhost:8080/api/v1/channels/999999/playback

# Без Basic Auth — 401 и WWW-Authenticate
curl -i http://localhost:8080/api/v1/channels
```

Единый формат ошибки:

```json
{"error":"channel not found or unavailable"}
```

## Административный API

Все запросы ниже требуют роль администратора (`admin:admin12345`). Для краткости в командах используется `-u admin:admin12345`.

### Пользователи

```bash
# Список
curl -i -u admin:admin12345 http://localhost:8080/admin/api/v1/users

# Создать пользователя 
curl -i -u admin:admin12345 -X POST http://localhost:8080/admin/api/v1/users 
  -H 'Content-Type: application/json' 
  -d '{"username":"guest01","password":"strongpass123","role":"user","active":true}'

# Выключить пользователя
curl -i -u admin:admin12345 -X PATCH http://localhost:8080/admin/api/v1/users/3 \
  -H 'Content-Type: application/json' -d '{"active":false}'

### Каналы

```bash
# Список, включая выключенные каналы
curl -i -u admin:admin12345 http://localhost:8080/admin/api/v1/channels

# Создать канал
curl -i -u admin:admin12345 -X POST http://localhost:8080/admin/api/v1/channels \
  -H 'Content-Type: application/json' \
  -d '{"number":6,"name":"Новости","stream_url":"https://stream.example.com/live/ch6/index.m3u8","active":true}'

# Выключить канал
curl -i -u admin:admin12345 -X PATCH http://localhost:8080/admin/api/v1/channels/6 \
  -H 'Content-Type: application/json' -d '{"active":false}'
```

`number` должен быть положительным и уникальным; URL потока должен иметь схему `http` или `https` и host.

### Подписки

```bash
# Просмотр всех подписок
curl -i -u admin:admin12345 http://localhost:8080/admin/api/v1/subscriptions

# Бессрочная включённая подписка
curl -i -u admin:admin12345 -X PUT http://localhost:8080/admin/api/v1/subscriptions \
  -H 'Content-Type: application/json' \
  -d '{"user_id":2,"channel_id":1,"enabled":true,"expires_at":null}'

# Подписка до конкретного момента (RFC3339; пример — UTC)
curl -i -u admin:admin12345 -X PUT http://localhost:8080/admin/api/v1/subscriptions \
  -H 'Content-Type: application/json' \
  -d '{"user_id":2,"channel_id":2,"enabled":true,"expires_at":"2030-01-01T00:00:00Z"}'

# Выключить подписку, сохранив запись
curl -i -u admin:admin12345 -X PUT http://localhost:8080/admin/api/v1/subscriptions \
  -H 'Content-Type: application/json' \
  -d '{"user_id":2,"channel_id":1,"enabled":false,"expires_at":null}'

# Удалить подписку
curl -i -u admin:admin12345 -X DELETE http://localhost:8080/admin/api/v1/subscriptions/2/1
```

`PUT` выполняет upsert: создаёт подписку или обновляет существующую. `expires_at: null` означает отсутствие срока окончания; прошедшее время означает, что доступ уже истёк.

## Проверки

При установленном Go 1.26+:

```bash
go fmt ./...
go test ./...
go vet ./...
go build ./...
```

Тесты unit-level не требуют PostgreSQL или Docker. Они проверяют строгий JSON-декодер, валидацию и работу кэша, включая защиту от выдачи устаревшего результата после инвалидирования. Dockerfile выполняет `go test`, `go vet` и `go build` на этапе сборки.

## Архитектура и решения

- **Один процесс и несколько файлов.** Для небольшого задания это проще микросервисов и DI-фреймворка; границы ответственности видны по файлам.
- **`net/http` и `ServeMux`.** HTTP-сервер, маршруты, JSON, middleware и логирование используют стандартную библиотеку.
- **`pgx/v5/pgxpool`.** Драйвер PostgreSQL и пул соединений; стандартная библиотека Go не содержит PostgreSQL-драйвера. SQL параметризован (`$1`, `$2` и т. д.), ORM нет.
- **`golang.org/x/crypto/bcrypt`.** Стандартная библиотека не предоставляет bcrypt.
- **Подписка на канал.** Это минимальная модель, подходящая для индивидуального доступа и простого администрирования.
- **Ответ без подписки — `404`.** Это решение скрывает наличие канала, который абонент не может смотреть.
- **Проверка срока на стороне БД.** Запрос использует `now()`, поэтому истечение подписки не требует фонового планировщика.
- **Список каналов кэшируется по ID пользователя.** Это необходимо, потому что доступный список индивидуален. Одновременные промахи кэша для одного пользователя объединяются в одну загрузку.
- **Кэш аутентификации хранит только успешные решения.** Ключ — HMAC от логина и пароля с секретным случайным ключом процесса; пароль в открытом виде в кэше не хранится. Максимальный размер ограничен.
- **Ограниченная свежесть.** Кэш успешной аутентификации допускает до 30 секунд задержки при изменении пользователя в другом экземпляре, а список каналов — до 5 секунд без учёта немедленной локальной инвалидизации. Для подписок с ограниченным сроком кэш списка истекает не позже даты окончания ближайшей подписки; endpoint playback всё равно проверяет подписку непосредственно в PostgreSQL. В этом приложении административные изменения очищают кэш текущего процесса.
- **Структурированные логи.** Логируются метод, путь, статус, размер ответа и длительность; заголовки и тело запроса не логируются.
- **Graceful shutdown.** После сигнала новые соединения перестают приниматься, текущим запросам даётся до 10 секунд завершиться, затем закрывается пул БД.

## Кэширование и высокая нагрузка: компромиссы

Этот вариант снижает повторные обращения к PostgreSQL для популярных пользователей и защищает от одновременного cache miss по списку каналов.
Кэш локален для процесса. При двух экземплярах A и B административный запрос к A не инвалидирует кэш B. TTL ограничивает окно устаревших данных, но не даёт строгой согласованности. Для нескольких экземпляров разумное дальнейшее развитие:

1. PostgreSQL `LISTEN/NOTIFY` или Redis Pub/Sub для уведомления всех экземпляров об изменениях;
2. общий кэш (например Redis) только при подтверждённой необходимости;
3. rate limiting на reverse proxy, TLS, мониторинг hit/miss и latency;
4. нагрузочный тест с профилем реального трафика, настройка пула и лимитов соединений;
5. при высокой стоимости Basic Auth — короткоживущие токены после отдельного входа.
